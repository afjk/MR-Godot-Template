# リアルタイム複数平面検出

深度から**複数の平面を同時に**見つけ、フレーム間で追跡するサンプルです。このリポジトリの中で、AR Foundationの`ARPlaneManager`に一番近いものを自作しています。

事前スキャンは要りません。机を動かせば追従します。

## なぜ自作するのか

Quest 3のOSはリアルタイムの平面検出を提供しません。**AR Foundationを使っても同じ**で、Meta OpenXRはSpace Setupで事前スキャンした部屋データを返すだけです（[調査メモ](../../docs/realtime_spatial_investigation.md)）。

材料であるDepth APIは公開されているので、ARCoreがやっていることを自分で書けば実現できます。これはその実装です。

| | [平面検出](../plane_detection/) | [リアルタイム平面推定](../realtime_planes/) | このサンプル |
| --- | --- | --- | --- |
| データ源 | 事前スキャン | 深度マップ | 深度マップ |
| 枚数 | 部屋のぶん全部 | **1枚**（視線の先） | **複数**（視界全体） |
| 境界 | ○ | ✕ | ○（矩形） |
| 追跡 | runtime任せ | なし | ○ |
| 机を動かしたら | 動かない | 追従する | 追従する |

## 手順

### 1. 点群にする

`DepthGrid.sample()`で48×48に間引き、XRの基準空間の点にします。

### 2. 法線を出す

上下左右の隣との差ベクトルの外積です。**隣同士ではなく、必ず反対側の隣まで使います。**

```gdscript
var tangent_u: Vector3 = right - left
var tangent_v: Vector3 = down - up
var normal := tangent_u.cross(tangent_v).normalized()
```

深度にはノイズが乗るので、近い2点の外積は向きが安定しません。1マス飛ばして差を取るだけで、見違えるほど落ち着きます。

### 3. まとめる（領域拡張）

種を1つ選び、四方の隣を見て次の2つを満たすなら同じまとまりに入れる、を繰り返します。

- 法線の向きが近い（内積 > 0.94、およそ20度以内）
- 種の平面からの距離が近い（5cm以内）

格子構造があるので、四方の隣を見るだけで済みます。**印を付けるのは、取り出すときではなく積むときです。** そうしないと同じ点が何度も積まれます。

### 4. 平面にする

重心と、点ごとの法線の平均を取ります。共分散行列やPCAは要りません。**法線は既に点ごとに出してあるので、平均するだけで十分です。**

境界は平面座標へ射影して軸並行の矩形にしています。凸包のほうが実際の形に近くなりますが、コードは大幅に増えます。

### 5. 追跡する

前回の平面と`(法線, 原点からの距離)`が近ければ同じ平面とみなし、番号を引き継ぎます。番号が変わると色も変わるので、**同じ面が同じ色のまま残るかどうか**が追跡できているかの目印になります。

## 調整するところ

| 定数 | 既定 | 効き方 |
| --- | --- | --- |
| `GRID_STEPS` | 48 | 増やすと細かくなるが処理時間が伸びる |
| `NORMAL_TOLERANCE` | 0.94 | 下げると曲面も1枚にまとまる |
| `PLANE_TOLERANCE` | 0.05 | 上げると段差を無視する |
| `MIN_CLUSTER` | 40 | 上げるとノイズ由来の小さい面が消える |

## 限界

- 深度のノイズがそのまま出ます。事前スキャンの平面のような安定感はありません
- 境界は矩形なので、L字の机や斜めの壁は実際より大きく出ます
- 更新は1秒に1回です。CPUへの転送がそれ以上に速くできません
- 有効範囲は約0.2m〜4m
- 48×48 = 2,304点をGDScriptで処理しています。重ければ`GRID_STEPS`を減らすか、GDExtension（C++）へ移すのが順当です

## 必要な設定

- `project.godot`: `xr/openxr/extensions/meta/environment_depth=true`（設定済み）
- OpenXR Vendors plugin

## 対応端末

Quest 3のみ。非対応端末では理由を表示します。
