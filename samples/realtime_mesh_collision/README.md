# 環境メッシュの当たり判定

深度から`ConcavePolygonShape3D`を作り、**実際の床や机でボールを跳ねさせる**サンプルです。

pinchでボールを投げます。

## なぜCPU経路なのか

[リアルタイム環境メッシュ](../realtime_mesh/)は頂点シェーダーで毎フレーム押し出すので速いのですが、**形がGPU上にしか無いため物理には使えません**。当たり判定が要るなら、深度をCPUへ落とすしかありません。

| | GPU（`realtime_mesh`） | CPU（このサンプル） |
| --- | --- | --- |
| 更新頻度 | 毎フレーム | 1秒に1回 |
| CPUコスト | ゼロ | それなり |
| 表示 | ○ | ○ |
| **当たり判定** | ✕ | **○** |
| 動く物への追従 | ○ | 遅れる |

代償は更新頻度です。GPUからCPUへの転送は安価ではなく、深度マップ自体も毎フレーム更新されるわけではありません。動いている物には追いつきませんが、**床・壁・机のような動かない面には十分間に合います**。

## 手順

1. `get_environment_depth_map_async`で深度をCPUへ落とす（1秒に1回）
2. 深度画像を40×40に間引き、逆行列で基準空間の点に戻す
3. 隣り合う4点で四角を作り、三角形2枚に割る
4. 三角形を`PackedVector3Array`にまとめて`ConcavePolygonShape3D.set_faces()`へ渡す
5. 同じ配列から`ArrayMesh`も作り、薄く表示する

```gdscript
var shape := ConcavePolygonShape3D.new()
shape.set_faces(faces)
_collision.shape = shape
```

## 実装で外せない点

**物の縁を捨てる。** 手前の物と奥の壁をまたぐ四角は、そのままだと壁まで伸びた板になります。ボールがその板で跳ねると明らかに不自然なので、四隅が`EDGE_THRESHOLD`（0.2m）より離れていたら三角形を張りません。表示だけなら多少の歪みは許せますが、**当たり判定では見えない板が効いてしまう**ので、こちらのほうが重要です。

**`StaticBody3D`は`XROrigin3D`の直下に置く。** 逆行列が返すのはXRの基準空間の座標です。原点の下に置けば、その座標をローカル座標としてそのまま使えます。recenterで原点が動いてもcollisionが一緒に動きます。

**間引きの粒度。** 40×40で三角形は最大3,042枚です。増やすと形は細かくなりますが、GDScriptでの構築時間がそのままフレーム落ちになります。1秒に1回とはいえ、その1回が長いと引っかかりとして見えます。

## 精度の限界

- 有効範囲は約0.2m〜4m
- 深度にはノイズが乗るので、平らな床でもわずかに凸凹します。小さく速い物ほど貫通しやすくなります
- 手も面として拾います。`set_hand_removal_enabled`で除外できます（[深度オクルージョン](../occlusion_depth/)を参照）

## 必要な設定

- `project.godot`: `xr/openxr/extensions/meta/environment_depth=true`（設定済み）
- OpenXR Vendors plugin
